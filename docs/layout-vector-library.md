# 版式向量库构建方案（v2：向量索引 + 软匹配）

> 状态：定稿。替代此前「硬聚类成少数簇 + centroid」的方案。
> 动机：单据版式是**连续分布**的（几乎每张都不同），硬聚类成少数簇会误分边界、丢失连续相似度信息。

## 1. 核心结论

**不做硬聚类，改做「向量索引 + k-NN 软匹配」。**

```
不做：doc_type → {cluster_id → centroid}           # 硬聚类，会误分
改成：doc_type → [代表图向量列表]                   # 保留版式多样性
匹配：新图 → 向量 → top-k 最近邻 + 相似度分         # 软匹配，不做硬归属
```

新任务样例图编码后，对索引做余弦相似度 top-k，返回「最像的 top-3 + 分数」。版式连续变化也没关系——总能找到「最近的那几张」，而不是被迫塞进某个不准的簇。分数低于阈值就如实说「无相似版式」，走 doc_type 粗推兜底。

## 2. 三个 cluster 角色彻底解耦

| 角色 | 用途 | 状态 |
|---|---|---|
| **训练 cluster**（8:2 split / ID-OOD） | 数据划分依据 | ❄ 冻结，只读，永不改写 |
| **近重复簇**（`cluster_XX`，阈值 0.9） | 标注阶段的去重结果 | 🔁 复用，仅用于「选代表图」 |
| **版式向量索引**（本方案） | 新任务版式匹配 | 🔨 新建，独立命名空间 |

关键：三者命名空间分开，互不覆盖。重建版式索引**不影响**训练数据划分（那是既成事实），也不改写近重复簇（那是 ground truth）。

## 3. 实测诊断结论（2026-08-14）

构建前先对 embedding 服务和聚类结果做了实测，结论如下：

1. **本地服务 = 公网服务**：同簇相似度标度一致（0.80/0.92 vs 0.81/0.92），dim 均 2048，配置正确、质量正常。
2. **版式向量有区分度**：跨单据 0.42~0.60（强），同簇 0.77~0.95。
3. **标注簇粒度严重不均衡**：并查集连通分量（阈值 0.9）导致「主流版式」聚成巨簇——aco 的 `cluster_00` 有 **306 张图**，而其余 8 簇只分到零散少数。大簇内两两相似度跨度 0.77~0.95（靠「相似链」传递连通，两端差异大）。
4. **单一代表图不可行**：即使选「簇内最中心图 medoid」，与簇内最远图相似度也只有 0.77，代表不了 306 图的巨簇。

**因此修正策略**：不选「每簇 1 张代表图」，改为「每簇存全量向量（大簇均匀抽样）」——真正贯彻软匹配，避免「代表图代表不了大簇」的问题。

## 4. 存储形态

```json
{
  "version": 1,
  "dim": 2048,
  "max_per_cluster": 50,
  "docs": {
    "pl_mixed": [
      {"cluster_id": "cluster_00", "image": "cluster_00/xxx_page001.png", "vector": [0.12, -0.03, ...]},
      {"cluster_id": "cluster_00", "image": "cluster_00/yyy_page001.png", "vector": [...]},
      ...
    ],
    "swb_mixed": [...]
  }
}
```

- 每个近重复簇存**全部图向量**；簇内图数超过 `max_per_cluster`（默认 50）时**均匀抽样**；
- `image` 存相对路径（脱敏后进公开仓库）；
- 不选代表图、不存 centroid——匹配侧直接对全部向量做 k-NN。

## 5. 匹配方式（检索侧）

```
新图 → embedding(2048 维) → 对同 doc_type 的全部向量求余弦相似度
  → 排序取 top-k（k=3）
  → 每项带 {cluster_id, score, image}
  → score < threshold 则判定「无相似版式」
```

不做「归到某个 cluster」的硬判定；`cluster_id` 仅作为「来源标注」附带返回。

## 7. 构建流程

```
遍历 8 单据 groups/cluster_XX/
  → 每簇全部图片（大簇均匀抽样到 max_per_cluster）
  → 调 embedding 服务（公网 9030）编码
  → 写 layout_index.json（每张图一个向量条目）
```

- 大簇（>50 张）均匀抽样到 50 张，控制索引体积；小簇全存。
- 一次性成本：全量图约数千张，每张 1~2s，总耗时约 1~2 小时（可后台跑）。

## 8. 与 profiler 的衔接

- `profiler.embed_layout_vector()` 已接入 embedding 服务（公网 9030，样例图 → 2048 维向量）。
- 匹配逻辑：由「归簇」改为「对 `layout_index.json` 做 k-NN top-k + 分数」。
- 不提供样例图时，仍 fallback 到 doc_type 粗推（保持零 GPU 可用）。

## 9. 待确认的决策点

1. **抽样上限 `max_per_cluster`**：默认 50，大簇只存 50 张均匀抽样（保留版式多样性、控制体积）。
2. **相似度阈值**：同簇分布 0.77~0.95、跨单据 0.42~0.60，建议阈值 0.75~0.80（仍需真实样例图校准）。
3. **索引落库位置**：构建产出于 A800，最终 `layout_index.json` 存 `phase2/data/`（与 claims/concepts 同库），脱敏后进公开仓库。
