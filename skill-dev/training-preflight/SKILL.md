# 训练前经验推荐（training-preflight）

基于「训练经验 Memory」的画像引擎 + 规则检索，为新的单据/字段抽取训练任务推荐历史经验。纯规则、零 GPU、本地 Python 即可运行。

## 何时使用

在以下场景触发本技能：

- 用户描述一个**新单据/字段抽取任务**（如「我要训练一个装箱单的货描抽取，字段有数量、毛重、净重、唛头」）。
- 用户给出**字段定义**（字段名 + 样例值），想知道有什么历史经验/坑。
- 用户询问「这类字段/单据训练有什么历史 badcase / 踩坑 / 建议」。

## 工作流

### 第 1 步：从自然语言提取结构化输入

从用户描述中提取两部分：

1. **单据类型** `doc_type`（可选，用于版式标签粗推）。识别关键词映射（与脚本 `_DOC_TYPE_ALIAS` 同步）：
   - 装箱单 → `packing_list`；商业发票 → `commercial_invoice`；提单 → `bill_of_lading`；海运单 → `sea_waybill`（**提单 BL ≠ 海运单 SWB，勿混**）；形式发票 → `proforma_invoice`；销售订单 → `sales_order`；托收 → `aco`；其他 → 留空用 `unknown`。
   - 版式索引只覆盖 8 类（装箱单/海运单/托收/贷记通知/借记通知/提货单/发货单/销售订单）；发票/提单等未覆盖时，脚本会提示「版式索引未覆盖」并跳过版式视觉确认，仅按声明类型匹配——这是预期行为，不是报错。
2. **字段列表** `fields`：每个字段提取 `name`（字段名或语义名）和 `sample`（样例值，可选）。

提取规则：
- 用户给了具体字段名（如 `goods_quantity`、`beneficiary_bank`）→ 直接用。
- 用户只描述语义（如「数量字段」「银行字段」「金额字段」）→ 映射到字段语义概念的常见别名（见 `references/concepts.md`）：数量=`goods_quantity`/`quantity`、金额=`goods_amount`、币种=`currency`、买方=`buyer`、收款行=`beneficiary_bank`、发票号=`invoice_no` 等。
- 有样例值就带上（值形态启发会用到：`USD 535.00`→金额、`2026-03-25`→日期、`10 CTN`→数量单位）。

### 第 2 步：调用 advise.py

构造 JSON 输入，调用统一入口脚本：

```bash
echo '{"doc_type":"packing_list","fields":[{"name":"goods_quantity","sample":"1,392 BAGS"},{"name":"goods_amount","sample":"USD 535.00"}]}' \
  | python3 <skill-dir>/scripts/advise.py
```

脚本完成：字段归一化到 canonical 概念 → 打能力标签 → 检索历史经验 top-k → 生成建议卡。输出为 Markdown。

### 第 2.5 步（可选）：样例图版式视觉确认

用户提供了**样例图**（图片路径），且环境配置了版式 embedding 服务 + 版式索引时，可对样例图做**版式视觉确认**——识别样例图真实属于哪种单据（纠正 doc_type 标错/拿错样例图），并给出版式结构标签（比 doc_type 名字粗推可靠）。

- JSON 里加 `image_path`（样例图路径）+ `embedding_server`（embedding 服务地址，如 `http://124.220.53.207:9030`）+ `index_path`（`layout_index.json` 路径）；或通过环境变量 `EMBEDDING_SERVER` / `LAYOUT_INDEX` 提供后两者。
- 未配置时脚本自动回退纯字段版，不影响使用。

单据缩写 ↔ 中文名对照（输出建议卡时会展示中文名）：

| 缩写 | 中文名 | 缩写 | 中文名 |
|---|---|---|---|
| pl | 装箱单 | do | 提货单 |
| swb | 海运单 | sdn | 发货单 |
| aco | 托收 | so | 销售订单 |
| crn | 贷记通知 | dbn | 借记通知 |

> 注意：数据目录名里的后缀（如 `swb_mixed`、`aco_non_goods`）**不是单据类型的一部分**，而是标注字段范围——`_mixed`=全字段标签、`_goods`=仅货描字段、`_non_goods`=仅非货描字段。单据类型只是前缀（`swb`/`aco` 等）。

### 第 3 步：把建议卡转成自然语言回复

脚本输出是结构化 Markdown。转述给用户时：

- **优先讲命中率最高的 2-3 条经验**，说明「问题模式 → 建议干预 → 失效边界」。
- **附上支撑证据**（哪条 Case、什么指标），让用户能追溯。
- **诚实标注状态**：`validated`（干预验证过）/ `confirmed`（归因确认）/ `candidate`（候选）。
- 若输出是「无匹配经验 → 回退默认 SOP」，如实告知没有命中历史经验，并提示「人工确认字段语义」。
- 明确声明：这些是**建议**，不自动改参数。
- 建议卡含三档信息：**候选策略**（直接命中）/ **命中机制**（机制命中但当前字段类型无实例，谨慎采用）/ **相近但未命中**（标签接近但被 lane/单据类型等适用性条件拒绝，供人工判断是否放宽）。转述时三档都要呈现，帮用户理解为什么推荐/为什么不推荐。

## 关键约束

- 本技能**只做训练前推荐**，不做训练后回灌（回灌是另一条链路，见项目 `phase3/`）。
- 检索是**规则匹配**（别名表 + 能力标签），无向量语义检索——对完全陌生的字段名可能命中不了，此时如实说「未命中」而非硬编造。
- 字段名会因单据而异，但能力标签稳定：优先靠**语义标签**（数量/金额/当事人/银行/编号…）匹配，而非字段名本身。
- 画像无任何字段信息（空画像）时不触发机制兜底——完全陌生的任务走「无匹配经验」诚实降级。

## 测试与回归

`tests/` 含 24 条回归测试（值形态启发中英文、doc_type 归一化、机制两级检索、③b 兜底、near-miss、索引未覆盖提示、端到端建议卡）。改动脚本后跑：

```bash
cd <skill-dir> && python3 -m unittest discover -s tests
```

## 输出示例

输入一个装箱单字段定义，脚本输出建议卡含：画像摘要（命中语义标签、值形态、版式）、候选策略（问题模式 + 干预 + 失效边界 + 证据）、保护条件提示。
